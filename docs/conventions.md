# Конвенции и работен процес

Домашните правила за промени в репото и как се проверяват. Важат за всяка задача; спецификите по пакети са в [architecture.md](architecture.md) и [testing.md](testing.md).

Адаптирано от `graphdb-workbench/docs/conventions/` — взети са само правилата, които не зависят от конкретния framework.

## Златни правила

1. Следвай стила, който вече се използва в целевия пакет (`apps/web`, `apps/api`, `packages/shared`).
2. Промените остават локални за пакета, освен ако споделена абстракция е очевидно нужна.
3. Предпочитай разширяване на съществуващи services, routes, schemas и hooks пред въвеждане на паралелни модели.
4. Споделен код между web и api се внася само през `@family/shared` (виж [architecture.md](architecture.md)).
5. Без широки рефакторинги, ако задачата не ги изисква.
6. Единственият писач в базата е `apps/api`. n8n, OpenClaw и PWA-то минават само през REST API-то.
7. AI контрактите са фиксиран JSON вход → изход, валидиран в API-то със schema. Без свободен чат.
8. При промяна на стилове — използвай design tokens (CSS custom properties) и провери светла и тъмна тема; дашбордът живее на TV и таблет.
9. Без ad hoc `console.*` в api — логвай през logger-а на Fastify (pino). В web — през един общ `logger` модул.

## Работен процес

**Преди редакция:**

- Прочети най-близкия `package.json`.
- Разгледай съществуващите модели в същата папка/модул.
- Потърси символа или функционалността в целия workspace, преди да въведеш нова абстракция.

**След редакция** — първо целеви проверки, после по-широки:

```bash
pnpm --filter <package> lint
pnpm --filter <package> test
pnpm --filter <package> typecheck
pnpm -r test            # преди commit
```

При промяна на Drizzle схемата — генерирай миграция и я прегледай преди commit:

```bash
pnpm --filter api db:generate
```

Ако промяната засяга runtime wiring (Docker Compose, Dockerfile, env, Caddy) — вдигни пълния стек локално по [infra/README.md](../infra/README.md) и провери ръчно.

## Definition of done

Една промяна е готова, когато:

- Кодът следва конвенциите на целевия пакет.
- Импортите спазват границите между пакетите.
- Lint и typecheck минават.
- Тестовете за засегнатия обхват минават.
- Промени в API контракт (route, schema) са отразени в `packages/shared` и в клиента.
- Нова таблица или колона има миграция.
- Стилове са проверени в светла и тъмна тема и на три ширини (телефон, таблет, TV).
